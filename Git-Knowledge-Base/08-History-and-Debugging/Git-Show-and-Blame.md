# Git Show and Git Blame

สองคำสั่งคู่หูในการแกะรอยประวัติและสืบหาที่มาของโค้ดในระดับลึก

---

## 1. `git show` — กล้องจุลทรรศน์ส่องดู Commit

ในขณะที่ `git log` ให้ภาพรวม `git show` ใช้สำหรับ **ตรวจดูรายละเอียด Metadata และการเปลี่ยนแปลงของ Commit แบบเต็มรูปแบบ**:

```bash
# ส่องดู Commit ล่าสุด
git show

# ส่องดู Commit hash ที่ระบุ
git show 8a4c12d

# ส่องดูเฉพาะไฟล์เดียวใน Commit นั้น
git show 8a4c12d:src/auth.service.ts
```
ผลลัพธ์จะแสดง Commit Header, ผู้เขียน, วันที่, ข้อความ และ Unified Diff ของการเปลี่ยนแปลงใน Commit นั้น

---

## 2. `git blame` — การสืบสวนหาที่มาทีละบรรทัด

- **ใช้ทำอะไร:** แสดงผลไฟล์โค้ดทั้งไฟล์ โดยระบุว่า **แต่ละบรรทัด ใครเป็นคนเขียน บันทึกไว้ใน Commit ใด และเขียนเมื่อวันเวลาใด**
- **เจตนารมณ์แท้จริง:** แม้ชื่อคำสั่งจะแปลว่า "กล่าวโทษ (Blame)" แต่วัตถุประสงค์ทางวิศวกรรมไม่ใช่เพื่อจับผิดเพื่อนร่วมงาน แต่มีไว้เพื่อ **"หา Commit Message และบริบทว่าทำไมโค้ดบรรทัดนี้จึงถูกเขียนขึ้นมาแบบนี้"**

```bash
# ตรวจสอบประวัติของไฟล์ src/config.js บรรทัดที่ 10 ถึง 20
git blame -L 10,20 src/config.js
```

**ตัวอย่างผลลัพธ์:**
```text
a1b2c3d4 (Somchai 2026-03-15 10:24:12 +0700 10) const MAX_RETRY_COUNT = 5;
e5f67890 (Wichai  2026-05-20 14:10:05 +0700 11) const TIMEOUT_MS = 30000;
```

เมื่อได้รหัส Commit `a1b2c3d4` มา เราสามารถใช้ `git show a1b2c3d4` เพื่ออ่านคำอธิบายว่าทำไม Somchai ถึงกำหนดค่า Retry เป็น 5 ได้ทันที!
